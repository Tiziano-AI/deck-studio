# Artifact choice and ownership

Use this when the destination, editability or reading needs can change the
medium. Resolve capabilities against the current inventory; these names are
recognition aids, not guaranteed installed dependencies. Load another skill
only for the distinct artifact work it owns.

| Actual need | Production route |
| --- | --- |
| Fixed-stage browser presentation, live or reading deck | Continue in Deck Studio with its runtime. |
| Editable PowerPoint or Google Slides | Use the available presentation skill, such as `presentations:Presentations`; preserve the semantic source and let that owner produce and inspect the editable artifact. |
| Memo, one-pager, proposal document or Google Docs-targeted material | Use the available document skill, such as `documents:documents`, when a document better serves the communication. |
| Searchable/selectable or semantically accessible PDF | Choose a text-bearing document/presentation/PDF producer before rendering; use `pdf:pdf` or `charter-document-fidelity` for the actual fidelity requirements. Deck Studio's screenshot export cannot supply these properties. |
| Workbook model, financial scenarios, metrics or chart calculation | Use `spreadsheets:Spreadsheets` or the actual data owner before relying on the results in slides. |
| New image or visual asset | Use the available image/visual capability for that asset; keep the deck's narrative and integration here. |
| Generic website, dashboard, application or unrelated hosting | Route to its product/website/provider owner. The Decks library is the only publication destination owned here. |
| Format-only edit to an existing document/PPTX/PDF | Route directly to its artifact owner, without a communication interview. |

When the user requests an editable deck, do not substitute a rasterized PDF,
HTML deck or images placed in PowerPoint. A proposal may be a deck or a
document; decide from the requested use, not the word "proposal".

For a live deck plus a leave-behind, produce the requested pair with shared
facts and different explanatory density. A board deck may need backup analysis;
a research readout may need a methodology appendix; an RFP may need a required
response structure plus a short executive deck. Do not create companion
artifacts without a real need in the task.

Carry the existing semantic source, audience, register, next action, modality,
evidence, constraints and user locks to the artifact owner. Avoid regenerating
a second brief. Preserve the chosen owner's proof obligations: document
rendering proves that document, HTML screenshots prove that HTML, neither
proves the other.

Accessibility also affects presentation behavior. Plan readable type, sufficient
contrast, non-color-only encoding, captions or transcripts for meaningful media,
and a text alternative for visually conveyed essentials. Fixed-stage phone
letterboxing is a scaling check, not proof of comfortable phone reading or
assistive-technology access.
