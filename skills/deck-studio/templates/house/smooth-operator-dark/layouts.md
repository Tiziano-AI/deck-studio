# Smooth Operator Dark layouts

- Title: large Raleway thesis, product mark, mono capability rail, one cockpit/control-plane object.
- Section: full-bleed dark stage, magenta/cyan route beam, one sentence that names the platform boundary.
- Architecture reveal: Browser/ChatKit, API edge, Run Supervisor, agents/tools, provider route, ResponseBundle/export.
- Run flow: lifecycle rail with states, active run highlight, stale/failure/recovery semantics.
- Evidence orbit: committed source, citation, artifact, export, and audit receipt arranged around a central response bundle.
- Cockpit demo: one large dark UI frame with sidebar/thread/widget zones abstracted as product surfaces, not fake app screenshots.
- Comparison: two or three glass panels with route/policy/evidence differences; keep the selected path visibly lit.
- Close: one confident recommendation and one operator action; no generic thank-you.

Density: medium. Strengths: title, architecture reveal, run flow, product cockpit. Weak cases: many small tables, legal or compliance fine print.

Use only structures supported by the locked content. Named architecture components and evidence fields above are possible composition slots, not mandatory product claims. Preserve qualifications and sources through any split; a blank slot must be redesigned, not filled with invented data.
